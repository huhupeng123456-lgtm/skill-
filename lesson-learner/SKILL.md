# Lesson Learner

Help the user learn long-form course materials by extracting complete knowledge points and giving objective analysis, then outputting to a Feishu document.

## Core Principle

**学习不是复制原文，而是把材料变成自己能用的知识结构。**

输出必须满足：
- 知识点完整，不遗漏课程中的关键概念
- 分析客观，不夸大、不美化、不编造
- 结构清晰，适合复习和查找
- 最终落到飞书文档，方便后续编辑和分享

## 🔴 CHECKPOINT 1：确认学习目标和材料

开始处理前，必须确认以下信息：

1. **课程材料在哪里？**
   - 视频/音频文件路径
   - 文本/课件/PDF 路径
   - 网页/课程链接
   - 如果材料需要下载或转录，先说明需要什么工具

2. **用户的学习目标是什么？**
   - 应付考试 → 侧重考点、定义、公式
   - 理解原理 → 侧重推导逻辑、因果链
   - 落地应用 → 侧重方法、步骤、案例
   - 泛泛了解 → 侧重核心结论和框架

3. **输出长度和深度？**
   - 精简版（1-2 页）
   - 标准版（覆盖主要知识点）
   - 详细版（含案例、延伸、个人思考空间）

**没有确认以上任意一项，不得开始提取知识点。**

## Workflow

### Step 1：读取和转录材料

如果用户提供的是视频或音频：
- 优先使用本地转录工具（如 Whisper）生成文本
- 如果无法转录，先告知用户并请求文本稿

如果用户提供的是文本/PDF/链接：
- 直接读取文本内容
- 如果链接无法访问，告知用户并提供替代方案

### Step 2：识别课程结构

在提取知识点前，先列出课程的整体骨架：

```text
课程结构：
1. 主题 / 标题
2. 章节划分
3. 每个章节的核心问题
4. 章节之间的关系
```

### Step 3：提取知识点

每个知识点按以下格式输出：

```text
### 知识点 N：{概念名}

- 定义：用一句话说明这个概念是什么
- 为什么重要：它解决什么问题，不学它会怎样
- 关键细节：3-5 个必须记住的要点
- 常见误区：1-2 个容易理解错的地方
- 关联知识点：和前面哪个知识点有因果关系
```

### Step 4：客观分析

对课程内容给出客观判断，必须区分**事实**和**观点**：

- 哪些是课程明确陈述的事实？
- 哪些是讲师的个人观点/行业经验？
- 哪些结论有条件限制（如"在某些场景下"）？
- 哪些内容缺少证据或需要进一步验证？

**禁止**：
- 把讲师观点当成普遍真理
- 为课程补充没有来源的内容
- 用"显然""毫无疑问"等绝对化词语

### Step 5：输出到飞书文档

如果用户需要飞书文档输出：

1. 先在本机生成 Markdown 或 docx
2. 用户确认内容后，再协助上传到飞书
3. 如果用户授权飞书 API，按 API 规范创建文档
4. 最终给出文档链接和本地备份路径

如果用户不需要飞书，只输出本地文件即可。

## 失败模式处理

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 材料无法读取或转录 | 换格式重试（如视频→音频→文本） | 告知用户需要手动提供文本稿，无法自动处理 |
| 课程内容超长篇（>2 小时） | 按章节分段处理 | 建议用户分次提交，每次一个模块 |
| 知识点之间关系混乱 | 先画课程结构图，再填充细节 | 如果仍混乱，只输出"课程结构 + 核心结论"，不强行提取细节 |
| 用户目标中途变化 | 暂停并确认新目标 | 按新目标重新走 CHECKPOINT 1 |
| 飞书 API 不可用 | 先输出本地 docx/Markdown | 让用户手动上传到飞书，并提供格式说明 |
| 材料中有明显错误 | 标注出来，不替课程圆谎 | 如果错误影响整体理解，建议用户核对原课程 |

## 反例：不要做这些

| 反例 | 为什么不行 | 正确做法 |
|---|---|---|
| 直接复制课程原文当笔记 | 没有加工，无法帮助理解 | 用自己的话提炼知识点 |
| 把讲师每句话都记下来 | 信息过载，重点被淹没 | 按知识点框架筛选 |
| 编造课程里没有的例子 | 误导用户 | 标注"课程未提供案例"或请求用户补充 |
| 只给结论不给原因 | 用户无法建立理解 | 每个结论配"为什么" |
| 输出不区分事实和观点 | 用户容易被讲师立场带偏 | 明确标注"事实"/"讲师观点"/"待验证" |
| 一次输出几百页不拆分 | 无法阅读和编辑 | 按章节或模块分段输出 |

## Validation

输出前检查：

1. 所有知识点都有定义和"为什么重要"
2. 没有编造课程里没有的内容
3. 事实和观点已区分
4. 用户的学习目标已被满足
5. 飞书文档或本地文件路径已给出
6. 如果有无法处理的部分，已明确说明

## Final Response

保持简短：

```text
课程笔记已完成：
- 课程：{课程名}
- 知识点数量：{N} 个
- 输出位置：{飞书链接 / 本地路径}
- 学习目标：{目标}
- 注意：{任何需要用户手动确认或补充的事项}
```
