# 参考稿视觉继承与源稿保真工作流

用户提供参考 PPT、模板或完整演示稿时执行本工作流。目标是从零制作新稿,同时让成品在第一眼上仍属于参考稿的同一套视觉体系。不要把“参考”理解为只取相近颜色,也不要把“从零制作”误解为可以忽略原稿结构。

## 零、先通过四项门禁

### 1. 事实与用户否定

用户提供 Word、PDF、PPT、表格、知识库或其他权威材料时,建立“允许使用 / 用户否定 / 待确认”三类事实表:

- 可见文案只能来自“允许使用”项,并能回指源页、段落、表格或图片。
- 用户明确说“不属实”“不是这个业务”“不要放”后,该信息进入“用户否定”项。这个决定优先于源材料中的冲突表述,不得换词后再放回页面。
- 来源之间冲突且用户尚未判定时,保留为“待确认”,不为了完成稿件自行选择。
- 客户、案例、成果、收入、资质、团队规模和业务状态等高风险事实,未确认时不得使用。

### 2. 参考稿支持判定

开始制作前先判定 Dashi 的 `goal → HTML → 校验 → 导出` 链路能否承载参考稿的绑定设计系统。

- “支持”意味着背景、标题体系、字体层级、网格、页边距、页面密度、图片框和装饰语言都能在 Dashi 运行时中实现。
- 只能继承颜色、标题或页脚,而正文结构仍需换成通用主题时,判定为“不支持”。
- “不支持”时立即标记“阻塞”并说明缺口,不得改用 `python-pptx`、Office COM、手写 HTML 或其他链路生成近似稿后声称使用了 Dashi。

机器门禁:外部参考稿任务使用 `goal:scaffold --reference-bound` 与渲染包装脚本的 `-ReferenceBound` / `--reference-bound`。当前版本未注册外部参考稿主题,命令会以 `REFERENCE_BINDING_UNSUPPORTED` 停止；不得删除该标记后改用 `theme01`–`theme12` 近似生成。

### 3. 页数、容量与结构

- 先冻结事实,再决定页数。不设“至少 8 页”等凑页下限。
- 一页只承载一个清晰的阅读任务。事实少时合并页面,事实多时拆页或分层,不用装饰卡片扩充字数。
- 并列能力、业务类别或同级要点使用分栏、矩阵、平铺或分组结构,不得使用时间线或流程线暗示先后顺序。
- 只有源内容确实存在时间、步骤、路径或因果关系时,才使用 timeline/process。
- 不得在副标题、底部结论条和正文中改写后重复同一组事实,也不得连续多页复用同一骨架只替换标签。

### 4. Dashi 产物证据

只有同时满足以下条件时,才能对用户说“使用 Dashi PPT 制作”:

1. 本次任务新建了带 `artifactContract.version=1` 的 `goal.json`,而非复用旧任务文件。
2. Dashi 生成器由该 goal 渲染出 `ppt/index.html`、资源和 `dashi-build.json`。
3. `validate:goal-spec`、`validate:swiss`、`validate:goal-copy` 和 `validate:four-variant-quality` 均已通过,且报告核对同一 `workflowRunId`、goal 哈希、HTML 哈希和构建清单。
4. PPTX/PDF 由受验证的 Dashi 导出链路生成,并带同名 `.dashi-export.json`;只有 `verified:true` 才能称为已验证 Dashi 产物。

缺少任一环节时,只能说明实际使用的链路；旧稿可标记 `legacy-unverified`,不得用“Dashi 版”“按 Dashi 制作”等已验证表述。

## 一、先确定任务边界

1. 明确受众、汇报目的、交付语言、页数和格式。
2. 区分已完成成果、在建事项、建议和未来展望,不得混写状态。
3. 明确参考 PPT 承担的角色:
   - 视觉参考:继承设计系统,内容可重新组织。
   - 内容来源:除视觉继承外,还要保证章节和事实覆盖。
   - 页面结构参考:优先复用或映射现有页面骨架。
4. 默认不覆盖、不移动、不改写用户的原始文件。
5. 用户要求逐对象原位修改、保持对象 ID 或完全复刻母版时,先验证当前工具链能否做到；不能保证时停止并说明,不得用重新生成冒充原位编辑。

## 二、提取参考稿的视觉基因

至少检查 3 张具有代表性的页面；页面较少时检查全部。形成内部视觉基因清单,包括:

- 画布比例、背景颜色或背景图处理方式。
- 主色、辅色、强调色及其使用场景。
- 中文和英文字体、字号层级、字重、行距与标题位置。
- 页边距、内容网格、对齐线和常用留白尺度。
- 封面、章节页、正文页、图文页、数据页和结尾页的常见结构。
- 图片框的数量、位置、比例、圆角、描边、裁切和视觉重心。
- 卡片、线条、色带、阴影、编号、页眉页脚和装饰元素的使用方式。
- 单页信息密度、标题长度、正文行数和中英文主次关系。

把这份清单作为本次任务的绑定设计系统。存在参考稿时,不要再用一个“大致相近”的内置主题替代它。

## 三、识别源内容并建立覆盖表

内容来源包含 PPT、Word、PDF、表格或权威知识库时:

1. 识别标题层级、段落、表格、图片说明和章节顺序。
2. 建立“来源章节/页面 → 输出页面 → 保留、压缩或不使用的理由”覆盖表。
3. 保证原文各主要章节至少有明确去向；删除主要内容必须有用户授权或可说明的篇幅理由。
4. 从权威原文提炼“背景—实施内容—解决问题—业务价值”,不把单一数字替代完整项目逻辑。
5. 不新增来源中不存在的数字、结论、角色、项目状态或因果关系。
6. 来源冲突时保留待确认状态,不自行选择有利说法；用户已明确否定的信息则转入禁用清单,不再作为待确认项。

## 四、生成页面结构

先判断每页的内容关系,再选择结构:

| 内容关系 | 优先结构 |
| --- | --- |
| 三项或多项并列 | 横向平铺、矩阵或均衡分栏 |
| 前后变化 | 对比、箭头或左右分屏 |
| 连续步骤 | 横向流程、时间线或路径 |
| 上下层级 | 分层架构、树状或纵向递进 |
| 两张图片加说明 | 图文分栏或上下图带 |
| 单一结论 | 大标题、主视觉或单焦点页面 |

复用参考结构时,保持其模板骨架、图片位置、比例和视觉重心。新增结构时允许重新组合,但必须继承同一套色彩、字体、网格、留白、图片框和装饰语言。不要突然引入参考稿中不存在的卡片墙、霓虹科技风、渐变玻璃或其他强模板语言。

## 五、设计转折页

先判断前后页面的真实关系:

- 从全景到细节:架构下钻。
- 从一个业务到另一个业务:场景横向扩展。
- 从当前能力到下一阶段:能力演进。
- 从已完成到未来计划:未来展望。
- 从过程到结果:时间或因果推进。

只把面向观众的结论放到页面上,不要把“从上一页进入下一页”“这里开始讲”等制作说明写成可见文案。转折页文字保持精简,但不能为了短而删除必要逻辑。

## 六、保护图片与视觉锚点

1. 先确定图片在页面中的目标槽位、比例和构图安全区,再选择或生成图片。
2. 沿用参考结构时,默认保持图片框位置、宽高比、裁切方向、圆角和对齐关系。
3. 不拉伸图片,不随意改变横图和竖图比例,不为了填满页面而破坏主体。
4. 必须改变图片位置时,记录改变原因,并确认整体视觉重心仍与参考稿一致。
5. 图片内容必须与所在页面语义相符,不能因为画面好看而替换错误业务含义。

## 七、生成 PPT 配图候选

在 PPT 制作上下文中,用户要求生成照片、插图、主视觉或背景图时:

1. 根据最终槽位确定统一的宽高比、分辨率和主体安全区。
2. 默认生成 3 个独立候选；封面、章节页、关键转折页或用户明确要求时生成 5 个。
3. 候选使用相同的业务主题、视觉风格和画幅,只改变构图、视角、元素组织或氛围。
4. 每个候选独立生成,不得生成一张素材板或拼图再拆分。
5. 用 A/B/C/D/E 清晰标识并展示给用户,等待选择后再放进正式页面。
6. 用户明确说“不用选,直接定”时,可在内部比较候选后选择一张,并保留其余候选供追溯。

## 八、处理双语页面

1. 根据用户要求确定主语言和辅助语言,不得默认两种语言同等篇幅。
2. 中文为主时,中文承担标题和主要信息,英文缩小为辅助说明,但必须保证投影可读。
3. 保持同类页面的中英文字号、间距和位置一致。
4. 不为追求双语完整而挤压页面；正文过长时优先压缩、分组或拆页。

## 九、执行验收

### 内容验收

- 受众、目的和内容状态正确。
- 来源主要章节都有明确去向。
- 背景、实施内容、解决问题和业务价值没有被不当删减。
- 没有无来源数字、事实或因果关系。

### 视觉验收

- 将代表性参考页与成品页并排检查。
- 第一眼仍属于同一套演示稿。
- 背景、配色、字体层级、标题体系、网格、留白和页面密度一致。
- 图片框、裁切语言和装饰元素一致。
- 新增结构是原设计系统的自然扩展,不是另一个模板的拼接。

### 技术验收

- 不出现溢出、重叠、遮挡、裁切错误或错位。
- 图片不变形,素材路径有效。
- PPTX 文件能够在 Microsoft PowerPoint 中正常打开和继续编辑。
- 只有实际检查导出对象后,才宣称表格和图表为原生可编辑对象；不能验证时明确说明能力边界。

验收状态只使用“通过”“待修正”“阻塞”。任何绑定设计要求或事实要求无法满足时,不得降级后静默交付。
