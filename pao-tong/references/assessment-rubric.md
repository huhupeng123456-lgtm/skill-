# 真实能力验收规则

## 判定原则

“掌握”必须限定能力范围并由证据支持。一次成功、原案例熟练或概念复述，不能单独证明用户能处理变化、故障和未见任务。

学习中不展示固定学习板。按每轮证据调整提示强度，只在阶段完成或用户询问时汇总。

## 七项掌握证据

只有与当前能力地图相关的项目均通过，才能报告用户已掌握该范围。某项与目标确实无关时明确标为“不适用”，不能静默跳过。

| 能力 | 通过条件 | 可接受证据 |
|---|---|---|
| 对象与意义 | 能指出现实对象、当前语境含义及其输入输出 | 用户解释、真实样本、组件或字段定位 |
| 核心任务 | 用户亲手完成目标闭环，结果可复核 | 成果文件、界面状态、真实运行结果 |
| 机制模型 | 能说明关键判断、因果、状态变化和不变机制 | 预测、参数解释、数据流或方案取舍 |
| 条件变化 | 更换重要输入、参数、环境或业务条件后仍能完成 | 变式结果、差异解释、接收方证据 |
| 故障恢复 | 能根据现象和证据定位并修复相关故障 | 日志或 Trace、诊断、修复和回归结果 |
| 边界判断 | 能说明适用输入、风险、权限、生产差距和不能照搬处 | 边界说明、风险阻断、人工确认点 |
| 未见独立挑战 | 无逐步提示处理表面不同但结构同类的新任务 | 独立产物、运行证据和事后解释 |

固定对应或纯记忆任务不强求故障和复杂迁移，但必须按任务本身验收准确复现。程序性综合能力默认需要全部七项。

## 提示与独立性

- **完整支架**：明确入口、步骤、原因和观察点，只用于第一条成功路径。
- **部分支架**：只给目标、约束或排查方向，用于变式与纠偏。
- **模型调用**：只给任务、环境、边界和验收条件，用于独立挑战。

独立挑战中用户请求或接受决定性步骤提示，本轮立即转回练习。可以澄清目标、解释新术语和提醒安全边界，但不得透露核心操作顺序或最终配置。

## 证据检查

1. 证据来自当前环境和任务，不是旧截图或示例结果。
2. 结果证明目标状态，不只证明动作发生。
3. 关键配置、数据、日志或 Trace 可回溯。
4. 发送方打印不等于接收方收到；优先使用接收方状态和结果。
5. 目标主工具的能力不能由辅助终端或临时脚本替代。
6. GUI 证据同时证明控件功能身份和操作后的状态变化。
7. 同构机制可以沿用理解证据，但缺少当前组件证据时只能说“机制可迁移，组件未验证”。
8. Mock 只证明没有被替代的部分；被替代的核心能力保持未通过。
9. 高风险动作经过隔离、备份、预览或人工确认。
10. 未见案例与示范案例结构同类但表面不同，不能只是更换无意义文字或数字。

## 失败状态必须具体

根据实际证据选用以下结论，不笼统写“还没掌握”：

- **只记名称**：认识符号，未建立当前语境意义。
- **言存意空 / 下层不足**：会说定义，不能识别现实对象。
- **上层丢失**：已做多个案例，未抽出不变结构，换场景失败。
- **下上层错配**：有理论和经验，但对象归类或输入空间判断错误。
- **局部经验已形成、泛化不足**：原路径熟练，未见任务失败。
- **外显知识已有、内隐能力不足**：知道规则，但实时识别或操作不稳定。
- **程序性经验已有、模型不完整**：会做但无法解释输入输出或预测变化。
- **意义层已有、程序性能力未形成**：会解释但不能独立完成真实操作。

修复必须对准诊断：补对象与边界、比较案例抽象、检查输入空间、增加直接经验，或进入真实操作。不要统一“再解释”“多做题”或“多实践”。

## Mock 证据限制

- 规则程序替代大模型时，可验收路由、调用和解析，不能验收模型理解、Prompt 效果或自然语言鲁棒性。
- 静态结果替代真实工具或数据源时，可验收调用契约，不能验收数据准确性、认证、超时、幂等或业务成功。
- Mock 独立挑战只能验收 Mock 周围真实能力；更多 Mock 次数不能补足核心能力。
- 阶段结论写出替代对象、不能验收项、退出条件和下一条真实迁移路径。

## 完成报告

### 通过

- 完成的真实成果；
- 七项能力中适用项目的证据；
- 已知边界、生产差距和未覆盖范围；
- 下一项最小练习。

### 未通过

- 已通过部分；
- 具体失败状态及其证据；
- 尚缺的模型或程序性能力；
- 下一次只补练的最小任务。

不要因学习时间长、表达自信或大部分步骤成功而降低门禁。
