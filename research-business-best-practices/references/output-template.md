# 业务最佳实践扩展交付模板

仅在用户明确要求展开某项实践、生成 SOP/Playbook、查看完整证据或形成正式报告时读取本文件。默认一屏摘要直接使用 `SKILL.md` 中的模板。

## 1. 先选择一种交付物

| 用户意图 | 交付内容 | 不默认附带 |
|---|---|---|
| 展开第 N 项 | 只展开该实践的边界、步骤、角色、验收、失败和证据 | 其他实践、重复总览 |
| SOP / Playbook | 执行流程、责任、输入输出、验收和异常 | 研究过程、无关案例 |
| 查看完整证据 | 主张—来源矩阵、反例、局限和证据缺口 | 重复业务说明 |
| 正式报告 | 一屏摘要 + 必要正文 + 证据附录 | 装饰性图表和重复结论 |

所有交付物遵守：

- 先结论，后依据和执行细节；
- 用“直接采用 / 裁剪试点 / 暂不采用”形成互斥判断；
- 同一事实只放在一个位置，其他位置用编号回指；
- 摘要控制在一屏，详细证据放正文末尾或附录；
- 表格和图只在明显减少阅读成本时使用。

## 2. 单项实践展开

单项展开不超过 800 个中文字符，只回答用户选择的实践。

```markdown
### 实践：[名称]

**结论**：[直接采用 / 裁剪试点 / 暂不采用]，一句话说明原因。

**适用边界**
- 适用：
- 不适用：

**关键步骤**
1. [触发或输入]
2. [核心动作]
3. [输出与验收]

**角色与工具**
- 牵头：
- 协同/审批：
- 工具或模板：

**完成标准**
- [可观察、可复核的结果]

**主要失败与补救**
- [最可能发生的一项失败] → [补救动作]

**证据**
- [来源编号、链接、等级和局限]
```

只有流程存在返工、分支或多角色交接时才增加流程图。图后不再重复相同文字。

## 3. SOP / Playbook

先给一句话目标和适用边界，再使用一张主流程表：

| 阶段 | 触发/输入 | 关键动作 | 责任角色 | 输出 | 验收标准 | 异常处理 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

按需补充，不强制全部出现：

### 3.1 责任存在歧义时

| 决策/活动 | 执行 R | 负责 A | 协同 C | 知会 I |
|---|---|---|---|---|
|  |  |  |  |  |

角色不确定时写“待确认角色”，不得编造姓名或职务。

### 3.2 指标影响验收时

| 指标 | 口径与数据来源 | 目标/阈值 | 阈值依据 | 验收方式 |
|---|---|---|---|---|
|  |  |  |  |  |

没有依据的数字写成“建议试点目标”或“待验证阈值”。

### 3.3 多个高影响失败需要治理时

| 失败模式 | 预警信号 | 影响 | 预防/补救 |
|---|---|---|---|
|  |  |  |  |

只保留最可能或影响最大的 3—5 项失败。

## 4. 正式研究报告

正式报告按以下六层组织，摘要和正文不重复。

### 一、执行摘要

控制在一屏，正文不超过 500 个中文字符：

```markdown
**结论**：[一句话结论]（置信度：高/中/低）

| 判断 | 实践/边界 | 关键动作 | 验收/退出 | 依据 |
|---|---|---|---|---|
| 直接采用/裁剪试点/暂不采用 | 最重要的 1—3 项 |  |  | [E01] |

**会改变结论的边界或风险**
- 最多 1 条共同边界；单项边界写入表格。
```

### 二、研究范围

只写会影响结论的范围、假设和缺口，不复述项目背景。

### 三、实践与迁移判断

逐项使用“单项实践展开”模板。优先展开 P0/P1 项，低优先级内容放附录。

### 四、执行方案

需要落地时使用 SOP 主流程表；只有跨角色责任不清时增加 RACI。

### 五、风险、试点与下一步

| 项目 | 内容 |
|---|---|
| 最小试点 | 对象、范围和前置条件 |
| 成功标准 | 可观察结果 |
| 暂停/退出条件 | 触发停止的风险 |
| 下一步 | 最多 2 项，明确优先级 |

### 六、证据附录

使用第 5 节的证据矩阵。正文只用 `[E01]` 等编号回指。

## 5. 完整证据矩阵

每行只记录一个“主张—来源”关系：

| 编号 | 支持的主张 | 来源与直接链接 | 版本/精确定位 | 等级与支撑关系 | 局限 |
|---|---|---|---|---|---|
| E01 |  | 发布者、标题、发布日期、访问日期、URL 或内部文档 ID | 版本、章节、页码、表号或关键数据位置 | A—E；直接支持/间接支持/反对/背景 |  |

执行规则：

- 关键主张必须能回指证据编号；
- 法规和标准注明现行、修订或废止状态；
- 无法打开原文的来源只作为线索；
- 外部来源与内部来源分开标识；
- 外发版删除内部路径、原始摘录、人员身份和未获发布授权的事实；
- 无法回指的内容标为迁移建议、试点假设或待验证项。

## 6. 可视化选择

| 信息关系 | 适合形式 |
|---|---|
| 三项以上同类比较 | 简洁表格 |
| 三步以上且存在返工、分支或角色交接 | 流程图 |
| 条件改变动作或责任 | 决策图 |
| 单一事实或简单顺序 | 短句或编号列表 |

不要为了满足格式而制图。表格原则上不超过 7 列；管理摘要不超过 5 列。Mermaid 节点只放短语，详细动作和验收放在流程表中。Word、飞书文档和演示文稿使用载体原生表格或形状。

## 7. 交付前检查

- 第一屏能否让用户完成判断；
- 分类是否互斥，是否遗漏关键选项；
- 是否只展开用户需要的层级；
- 同一事实是否重复出现；
- 实践是否有动作、边界、验收和证据；
- 无依据阈值是否标为试点目标或待验证；
- 证据是否能定位到原文，法规和标准是否核对有效状态；
- 是否暴露内部敏感路径、原文或人员信息；
- 图表是否确实比短文字更容易理解；
- 证据不足时是否标明“部分完成”和缺口。
