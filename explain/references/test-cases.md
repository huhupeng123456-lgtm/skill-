# Explain Skill 测试案例

这些案例用于更新后的人工前向测试。检查真实回答是否形成可迁移的判断能力，不要求匹配固定标题或措辞。

## 案例 1：用户真实短问法

**用户请求**：解释下，什么是 Agent？

**验证能力**：

- 不要求用户先补充一套专业问题，能从真实短问法直接开始；
- 说明当前采用的是常见 AI 工程语境，不把单一厂商或课程定义当作唯一标准；
- 用“目标 → 判断下一步 → 执行 → 根据结果调整”的关系链解释；
- 给出可用于判断新系统的少量关键条件；
- 用典型 Agent、固定工作流反例和单工具边界例训练判别；
- 用一个未出现过的新系统检验用户能否判断，而不是让用户复述定义。

完整的已验收回答见 [approved-example-agent.md](approved-example-agent.md)。

## 案例 2：相似概念辨析

**用户请求**：RAG 和微调有什么区别？都能让模型懂公司知识，为什么不是一回事？

**验证能力**：

- 不只并排给定义；
- 比较输入对象、改变的位置、输出作用、更新成本与适用场景；
- 用同一个企业知识变更案例说明为什么应判为一种方案而不是另一种；
- 给一句可以在新需求中复用的选择规则，不把复杂选型压成绝对二选一。

## 案例 3：用户提供自定义课程语境

**用户请求**：这门课规定“只有能自主选择工具并根据结果继续行动的系统才叫 Agent”。请按这门课解释 Agent。客服机器人只按固定流程调用一次接口，算不算？

**验证能力**：

- 优先使用课程给定定义，不用通用定义覆盖；
- 把课程观点与 Agent 的补充说明明确分开；
- 按课程中的判断条件评估客服机器人；
- 若信息不足，指出需要确认的是固定流程还是会根据返回结果再次决策。

## 案例 4：会背定义但不会判断案例

**用户请求**：我知道缓存击穿的定义，但线上一超时我就不会判断。你教我怎么识别，不要再背定义。

**验证能力**：

- 识别用户缺的是判别模型；
- 给出需要观察的事实和判断顺序，而非直接跳到修复动作；
- 用正例、相似但不属于缓存击穿的反例训练边界；
- 再给一个未见案例让用户判断，并根据可能答案定位误区。

## 案例 5：知识与决策

**用户请求**：有人说“重要会议必须提前一天发材料”，这到底是知识，还是一个决策？为什么？

**验证能力**：

- 从建议中分离可泛化关系与当前行动；
- 说明决策依赖的目标、参与者和时间约束；
- 不把“提前一天”包装成所有会议都成立的规律；
- 给出条件变化时决策如何变化的边界例。

## 案例 6：判别模型、处理模型与输入空间

**用户请求**：大量请求超时，是不是数据库连接池耗尽？如果是，我接下来该做什么？这套判断对所有超时都适用吗？

**验证能力**：

- 先区分“是否属于连接池耗尽”与“确认后如何处理”；
- 判别阶段列出需要的证据，不凭症状直接确诊；
- 处理阶段只在条件成立时给动作；
- 说明这套知识的输入范围、能输出什么、不能排除哪些其他原因。

## 案例 7：复选框与触发条件是否必要

**用户请求**：为什么要新增“是否已创建过期工单”复选框，还要加触发条件？直接到期建单不行吗？

**验证能力**：

- 先指出已观察到的失败：同一张证照在重复触发时可能生成多张过期工单；
- 解释复选框是源证照上的“本次过期事件已处理”标记，触发条件是建单前的门卫；建单成功后回写为已勾选；
- 先检查现有的反向关联“关联工单为空”能否稳定替代；若能，明确不新增复选框；
- 只有在反向关联不可用、不可靠，或同一证照允许保留多张历史工单而需要单独标识当前过期事件时，才把复选框判为必要；
- 说明“资料确认状态”只代表证照信息已核对，不能表示已建工单；工单“处理状态”在建单后才存在，不能阻止重复创建；
- 给出不加时的具体后果和验收证据。

## 案例 8：拒绝冗余新增

**用户请求**：已经有稳定的“关联工单为空”条件，还要不要再建“是否已建单”复选框？

**验证能力**：

- 把复选框明确判为“冗余”；
- 说明两个状态表达同一约束会产生同步风险；
- 复用现有“关联工单为空”作为触发门禁，并说明何时结论会改变。

## 案例 9：从点击问题切换到因果问题

**用户请求**：先告诉我点哪里。等等，为什么要加这个触发条件？

**验证能力**：

- 纯点击部分交给操作陪练；
- 用户提出因果问题后立即暂停点击步骤；
- 先解释目标、失败、最小缺口、替代方案、删除后果和验收证据，再继续操作。

## 通过标准

每个回答至少满足下列可观察条件：

1. 保持当前语境和来源边界；
2. 有可执行的 X / 非 X 判断依据；
3. 例子服务于判断，且解释为什么属于或不属于；
4. 不混淆识别与处理、知识与决策；
5. 抽象层级与用户任务匹配；
6. 学习型请求用未见案例检查迁移，而不是只让用户复述定义。
7. 涉及结构性新增时，先完成替代检查和必要性判断；现有能力能稳定替代时，拒绝新增冗余组件。
