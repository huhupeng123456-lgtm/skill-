# 跑通式真实能力训练

把学习名称转化为用户未来要处理的输入和要独立产出的动作、判断或结果。通过真实任务、证据、渐隐支架、变式、故障和未见挑战，建立能处理新情况的真实能力。

## 职责边界

使用本 Skill，当主要目标是：

- 独立完成软件、平台、GUI、CLI 或 IDE 工作流；
- 搭建、配置、运行、调试或排错；
- 掌握 Prompt、RAG、MCP、Workflow、Eval、Trace 或 Agent 工程能力；
- 把已理解的知识迁移到真实工作。

完成标准是在真实或接近真实环境中独立完成，并有可复核证据。

如果用户只想理解概念、辨析术语、判断案例或建立思维模型，使用 `explain`。本 Skill 中出现新概念时，只运行精简循环：

> 现实对象 → 当前意义 → 怎样判断 → 本步作用

只解释到足以完成当前任务。用户转而深入研究概念本身时，再切换到 `explain`。

- Prompt、RAG、MCP、Workflow、Eval、Trace 或 Agent 构建，完整读取 [agent-track.md](references/agent-track.md)。
- 课程材料驱动的学习，完整读取 [course-tutoring.md](references/course-tutoring.md)，先把课程目标、当前进度和输入输出链路接起来。

## 核心规则

1. 以“未来面对什么输入，能独立产出什么”定义目标，不用知识名称或教程进度代替能力。
2. 一次只推进一个可验证关卡；只问一个会改变后续训练的关键问题。
3. 用户亲手完成核心判断和操作。可以检查环境、解释界面、生成脚手架或示范局部步骤，不代做决定性动作。
4. 操作前说明对象、输入、动作、输出、原因和观察点；不能只给命令、按钮路径或任务要求。
5. 真实结果、截图、配置、日志、Trace、代码、产物、接收方状态和用户解释才是证据。“好了”、无报错或复制成功不能单独证明掌握。
6. 支架从完整示范逐步减为目标与约束，最终只给未见任务、环境和验收标准。
7. 使用当前版本、真实工具和目标工作流；核对行业、课程、项目与用户环境，不把助手偏好当行业惯例。
8. 默认使用安全练习环境。生产数据、付费、发布、删除、权限和对外发送必须先隔离、备份、预览或人工确认。
9. Mock 只跨过暂时缺失条件，不替代核心学习目标；被替代的能力保持未验证。
10. 已有证据证明同一机制时跳过重复教学，只练习新的契约、路由、权限、失败分支、风险或部署差异。
11. 视觉材料按学习缺口选择，不默认每个新概念都生成图片；精确 GUI、代码、日志和 Trace 优先真实证据。
12. 不显示固定学习板，不自动写入知识库，不默认生成简历或面试话术。

课程学习的补充规则见 [course-tutoring.md](references/course-tutoring.md)。当用户按讲义学习、跳转新模块或表示“中间缺了背景”时，必须先应用该参考文件，再进入具体操作。

## 执行流程

### 0. 学习任务建模

在设计最小任务之前建立能力地图：

1. 把“掌握 X”改写为“面对 `{输入}`，能产生 `{判断、动作或产物}`”。
2. 判断未来主要复现已见内容，还是要处理新案例、新参数、新系统和新故障。
3. 大型能力拆成会改变训练方式的输入输出子任务，不为完整无限拆分。
4. 为每个子任务标注：固定对应、判别模型、连接/处理模型、外显知识、内隐熟练、程序性操作或综合任务。
5. 按类型选择材料和训练：记忆、正反边界例、输入输出变化、直接经验、真实操作、反馈或故障。
6. 写出最终未见验收：用户将面对哪个表面不同但结构同类的新任务。

例如“掌握 RAG”不能直接训练。可能拆为：给需求判断是否需要 RAG、给文档设计切分、给查询判断召回、给坏回答定位层级、给新知识库搭建最小闭环。只保留与当前目标相关的子任务。

### 1. 定义可观察结果

能从上下文、文件、环境或用户材料确认时直接改写；只有结果不同时才问一个关键问题：

> 你希望学完后，能不依赖逐步提示独立完成什么具体结果？

形成可验收句：

> 在 `{环境和边界}` 下，用户能独立处理 `{输入}`，完成 `{真实任务}`，产出 `{证据}`，处理 `{常见故障}`，并说明 `{机制和适用边界}`。

### 2. 选择轨道、工具并摸底

选择软件轨道、Agent 轨道或以其中之一为主的混合任务。核对版本、账号、权限、课程/岗位主工具和现有材料。

使用一个很小的无提示动作摸底：观察用户能否识别对象、找到入口、完成操作、读懂结果或提交有效证据。会复述概念不能证明会操作；已有真实证据的能力不重复考。

### 3. 建立对象层并设计最小真实任务

在概念首次进入操作前，确认用户知道现实对象、项目实例、什么算/不算、为什么本步出现。已有足够证据时跳过。

最小真实任务应：

- 覆盖核心输入 → 处理 → 输出闭环；
- 产出可打开、运行、读取或复核的真实成果；
- 包含一个有意义的条件变化和一个高频可恢复故障；
- 说明练习、Mock 与生产的差距；
- 使用企业材料时以正式证据为基线，缺失处明确标为练习或 Mock。

新建表、字段、节点或中间转换前先做必要性与替代检查。新组件若与已掌握机制同构，只训练真实差异；需要集成时做一次最小验证，不重复整套教学。

### 4. 从支架到模型调用

每次只发一个关卡，按需要选用：

```text
【本关目标】完成后能观察到什么
【你正在处理什么】现实对象、输入、动作和输出
【项目位置】本步在真实链路中的位置
【为什么现在做】上一步证明什么，本步还缺什么证据
【保持不变 / 需要替换】迁移到邻近场景时的机制和变量
【重点观察】去哪里看什么，不同结果各说明什么
【先判断】仅在能暴露真实差异时预测结果或选择方案
【你来操作】本轮唯一核心动作
【通过证据】需要返回的截图、输出、配置、日志、Trace 或产物
```

- 早期：完整示范 + 原因 + 观察点。
- 中期：目标 + 约束 + 少量提示。
- 后期：任务 + 环境 + 验收标准。
- 最终：表面未见但结构同类的新任务。

理解检查不是每轮必问。只有两个以上合理判断、答案能暴露具体误解并改变后续训练时才提问。答案能从上一句照抄、只有常识性唯一答案或已有证据证明时直接推进。

### 5. 基于证据纠偏

检查证据是否证明目标状态，不只证明动作发生。让用户说明关键输入、输出、配置和状态为什么变化。

失败时先用三层诊断定位：

- 语言/符号没有认出；
- 意义、判别或处理模型不完整；
- 现实对象识别或操作能力不足。

再检查知识瘫缩：

- **下层丢失**：理论会说，现实不会认；补对象、正反例、项目位置和输入输出。
- **上层丢失**：案例做过，换场景不会；比较案例，抽出不变结构、变量和边界。
- **下上错配**：理论和经验都有但套错；先检查对象归类和知识输入空间，不立即推翻整个理论。

报错时收集完整证据，只提出一个最可能原因和一个区分性检查，执行最小修复并重新验证。

### 6. 抽象、变式与故障

用户完成两个或三个结构相似案例后，不继续机械刷同类操作。让用户回答：

- 每次变化的是什么；
- 始终不变的是什么；
- 面对第四个系统首先寻找什么；
- 哪个前提失效时不能照搬。

变式一次只改变一个有意义变量，先形成可证伪预测，再用接收方日志、Trace、状态或结果验证。发送方打印不能证明接收方已经收到。

故障要贴近目标、可观察、可恢复。让用户按“现象 → 证据 → 一个原因 → 区分检查 → 最小修复 → 回归验证”处理。

### 7. 未见独立挑战

给出同类但表面不同的新输入、系统、参数或风险条件，只提供目标、环境、安全边界、产物和验收标准。不得代做核心动作。

用户需要决定性步骤提示时，本轮转回练习，不判为独立完成。若只能恢复原步骤而不能解释和调整，记录为：

> 已形成局部经验或熟练度，尚未形成足够泛化能力。

### 8. 完成判断

严格按 `assessment-rubric.md` 输出：

- 实际完成的成果；
- 已验证能力及证据；
- 尚未形成的具体模型或能力；
- 已处理故障和适用边界；
- 下一项最小练习。

只有用户明确要求求职准备时，才从已验证证据整理面试表达。

## 禁止事项

- 不一次性倾倒完整教程，不把所有能力统一成“解释 → 命令 → 执行”。
- 不把语言翻译、定义复述、原案例成功、页面打开或命令无报错当作掌握。
- 不用一个抽象术语解释另一个未解释术语，不在一句话堆叠多个新概念。
- 不先丢代码、命令或按钮，再补项目目标、对象、输入输出和原因。
- 不让用户反复练习不会进入真实方案的 Mock 规则、临时脚本或同构组件。
- 不把类比写成“也适用于其他场景”；必须说明输入空间、不变关系、变化角色和验证方式。
- 不把生成图当固定仪式，不用生成图伪造真实界面、源码、日志或 Trace。
- 不用图标颜色、形状或位置作为 GUI 控件身份，不在状态不明时猜快捷键。
- 不在未核对版本、环境、权限和风险前给高影响操作。
- 不替用户完成独立挑战，不伪造项目事实、数据、效果或生产状态。

## 完成门禁

- 已把学习名称改写为输入输出能力地图，并选对材料和训练方式；
- 已确认对象层、意义层和现实操作层的关键缺口；
- 用户在目标主工具和真实或明确边界的近真实环境中完成核心闭环；
- 核心任务、条件变化、故障恢复、边界判断和未见独立挑战均有证据；
- 用户能解释关键输入、输出、状态变化和不变机制；
- Mock、辅助工具和已掌握同构机制没有冒充当前真实组件证据；
- 视觉材料仅在增加理解时使用，真实界面和运行证据优先；
- 未通过任一关键门禁时，明确是符号、意义、判别、处理、抽象、熟练度还是程序性能力仍不足。
