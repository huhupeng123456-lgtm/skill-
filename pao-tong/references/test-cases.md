# Pao-tong 行为测试

用于人工或独立前向测试。不要只检查回答是否出现“真实任务、日志、变式”等词；判断 Skill 是否建立了正确能力地图、选择了合适材料和训练方式，并用未见任务与证据验收。

## Pao-tong 专项案例

### 1. 理论很多但没有现实对象层

**请求**：我会背 A2A、MCP、客户端和服务端，但看着三个运行窗口，不知道谁在调用谁。带我跑通。

**验证**：先定位真实程序、端口、地址、调用双方和请求返回；不继续堆协议定义；用户能在当前窗口和代码中指出对象后再操作。

### 2. 多个案例做过但没有抽象

**请求**：我已经照着做了三个 MCP 工具，第四个还是得重新看教程。

**验证**：诊断为上层丢失；比较三个案例，抽出不变契约和变化字段；第四个作为未见任务，不再重复前三个的完整步骤。

### 3. 套错概念导致错误方案

**请求**：所有超时都是网络问题，所以我准备给 RAG 检索加重试。带我改。

**验证**：先检查现实故障是否被判入正确类别、是否超出原知识输入空间；用 Trace 或日志做区分性检查；不立即执行错误方案，也不推翻所有网络知识。

### 4. 只会复制命令

**请求**：我能复制命令启动服务，但换个端口就不知道改哪里。

**验证**：识别为程序性经验但模型不完整；解释程序、参数、配置来源、持续状态和观察点；用端口变化让用户预测并修改，而非再给完整命令。

### 5. 已会基础机制，新组件同构

**请求**：第一个 Agent 和 MCP 服务我已经用日志、断点和故障恢复跑通。第二个只换业务字段和端口，还要全部重练吗？

**验证**：比较输入契约、处理、输出、依赖与风险；相同机制跳过，只练真实差异和一次最小集成；分别记录“机制已掌握”和“新组件是否验证”。

### 6. 操作成功但不能预测变式

**请求**：工作流成功跑了一次，但如果工具返回空值，我不知道会怎样。

**验证**：不判为掌握；建立输入变化与状态/输出的连接模型；先形成可证伪预测，再用接收方状态或 Trace 验证。

### 7. 知道规则但实时能力不足

**请求**：我知道调试要看活动会话，但多个窗口一出现我还是经常点错停止按钮。

**验证**：诊断为外显知识已有、内隐操作不足；使用真实界面、功能名、会话身份和即时反馈做渐增练习；不再讲一遍抽象规则，不用生成图替代真实界面。

### 8. Mock 跑通但核心能力未验证

**请求**：我用 if/else 模拟大模型选工具已经跑通十次，能算掌握 Agent 工具选择了吗？

**验证**：明确只能验收外围路由与契约；模型判断能力未通过；停止刷 Mock，转向真实模型、Prompt/Schema/Eval 或报告阻塞。

### 9. 未见独立挑战

**请求**：我已在订单场景完成 Workflow 的正常路径、异常和恢复。现在检验我能否独立迁移。

**验证**：给表面不同但结构同类的新业务任务，只给目标、环境、边界与证据；若提供决定性步骤则本轮降级为练习；验收不变机制和输入空间边界。

### 10. 两个可行方案取舍

**请求**：这个审批规则既能写进 Prompt，也能写成程序校验。两个都能跑，怎么训练我做真实取舍？

**验证**：要求用户依据准确性、可解释性、变化频率、成本、风险、权限和维护责任判断；用一个条件变化测试决策；不把个人偏好包装成唯一最佳实践。

### 11. 语言材料转真实能力

**请求**：老师给了 RAG 教程和代码，我要学到能诊断新知识库，不只是复现课程。

**验证**：从教程提取能力地图而非摘要；交代任务和数据角色；用真实文档、查询、召回和 Trace 建立判别/连接模型；最终换新知识库验收。

### 12. 视觉材料是否需要

**请求**：我在真实 PyCharm 截图里找不到当前调试会话。要不要先生成一张教学图？

**验证**：不生成虚构界面；优先标注真实截图、核对功能名和会话状态。只有数据流或隐藏调用关系难理解时才选择生成图。

## 跨 Skill 路由案例

### R1. 只理解概念

**请求**：先解释状态机是什么，帮我判断合同审批算不算状态机，我今天不搭系统。

**期望路由**：使用 `explain`；以未见案例判断完成，不启动工程训练。

### R2. 从解释转入真实任务

**请求**：状态机概念我理解了。现在在飞书里带我独立搭一个审批状态流，并教我排错。

**期望路由**：使用 `pao-tong`；概念证据沿用，建立真实输入输出、操作、变式、故障和独立挑战。

### R3. 跑通中出现新概念

**请求**：继续接 API，但我第一次看到 Bearer Token，不知道它在这一步是什么。

**期望路由**：保持 `pao-tong`；用“现实对象 → 意义 → 怎样判断 → 当前作用”精简解释，随后回到接入任务。只有用户转而系统研究鉴权模型时才切换 `explain`。

## 总体通过标准

1. 学习名称被改写为输入输出能力地图；
2. 子任务按固定对应、判别、连接、内隐或程序性能力选择不同训练；
3. 对象层、意义层和现实操作层均有针对性证据；
4. 成熟的工程门禁、真实工具、版本、GUI/IDE 身份、安全和 Mock 边界被保留；
5. 图片按学习缺口选择，不是固定仪式；
6. 已掌握同构机制不重复教学，但新组件证据不被虚报；
7. 两三个案例后抽象不变结构，迁移时说明输入空间和失效前提；
8. 独立挑战使用表面不同的未见任务；
9. 失败结论具体到符号、意义、判别、抽象、熟练度或程序性能力；
10. 测试选择正确学习任务、材料和方式，不按关键词或标题计分。
