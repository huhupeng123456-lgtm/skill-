## 1. 最佳实践的判定标准

把“最佳实践”视为一个需要验证的主张。候选做法同时满足以下条件时，才可作为推荐实践：

- **问题明确**：解决的业务问题和目标清楚。
- **条件明确**：适用行业、规模、阶段、角色和约束可识别。
- **动作可复现**：步骤、输入、输出和责任清楚。
- **结果可观察**：存在结果数据、过程指标或可检查的完成条件。
- **证据可追溯**：能够追溯到原始来源。
- **风险已识别**：已说明失败模式、反例或不适用情况。
- **可迁移**：能够解释如何裁剪到目标组织。

只包含理念、口号、趋势或工具清单的内容，不属于完整最佳实践。

## 2. 双来源模型

### 2.1 外部公开来源

用于判断：

- 行业成熟做法和标准流程；
- 常见角色、指标和治理机制；
- 已公开的实施结果和失败经验；
- 法规、标准和行业约束；
- 不同组织的做法差异。

外部材料不能证明用户所在组织已经采用或具备该能力。

### 2.2 企业内部来源

用于判断：

- 当前流程、角色、系统和数据现状；
- 已确认的制度、决策和责任边界；
- 实际问题、历史失败和客户反馈；
- 迁移外部做法所需的改造。

内部个人意见、会议中间讨论和聊天消息不能自动代表正式制度或最终决策。

### 2.3 禁止混用

- 不用外部案例证明内部项目状态。
- 不用内部单一意见证明行业共识。
- 不把计划、提案或草稿写成已执行事实。
- 不把供应商宣称的效果写成客户已验证结果。
- 面向外部的交付物不得泄露内部敏感材料。

## 3. 研究问题拆解

把一个宽泛问题拆成以下检索面：

| 检索面 | 要回答的问题 |
|---|---|
| 定义与目标 | 该业务过程解决什么问题，最终价值是什么 |
| 适用边界 | 行业、规模、地域、阶段和前提有哪些 |
| 标准流程 | 常见阶段、顺序、决策点和交付物是什么 |
| 组织角色 | 谁负责、谁审批、谁协同、谁验收 |
| 工具机制 | 使用哪些系统、模板、会议和治理机制 |
| 指标验收 | 监控哪些指标，阈值依据和验收方式是什么 |
| 成功案例 | 哪些组织在什么条件下取得了什么结果 |
| 失败反例 | 为什么失败，哪些做法不能照搬 |
| 迁移条件 | 目标组织需要具备或补齐什么 |

为同一概念生成中英文、全称/简称、方法名/业务问题等查询变体。对近期变化明显的领域加入当前年份；对法规和标准搜索正式编号和发布机构。

## 4. 来源优先级

### 4.1 外部来源优先级

1. 法律法规、监管文件、国家或国际标准；
2. 政府、行业协会、标准组织和官方统计；
3. 企业官方制度、技术白皮书、年报、实施说明和可核验案例；
4. 同行评审论文、研究机构和有方法披露的调查；
5. 有方法说明的咨询报告、专业媒体和专家访谈；
6. 供应商营销材料、个人博客、社区讨论和聚合摘要。

优先级表示默认信任起点，不代表高优先级来源在所有问题上都正确。例如法规可证明合规要求，但不能单独证明某一运营方法效率最高。

### 4.2 内部来源优先级

1. 已审批制度、合同、SOW、正式验收口径和最终决策文件；
2. 正式业务系统数据、审计记录和已确认报表；
3. 发布版方案、项目文档和责任人确认记录；
4. 会议纪要、访谈记录和客户反馈；
5. 聊天消息、个人笔记、草稿和待处理材料。

出现冲突时，优先核对时间、版本、审批状态、责任人和适用范围，不机械采用排序更高的旧材料。

## 5. 证据等级

证据等级评估“来源对当前主张的支撑强度”，不评估做法对目标组织的适用性。迁移性必须另行判断。

| 等级 | 定义 | 典型来源 | 使用规则 |
|---|---|---|---|
| A | 约束性或高度可信的一手证据 | 法规、正式标准、审计数据、已审批内部制度、签署文件、最终决策 | 可支撑明确事实或要求，仍需核对日期和范围 |
| B | 强一手证据或方法严谨的独立研究 | 官方统计、同行评审研究、权威行业组织、正式业务系统数据 | 可支撑重要判断，说明研究方法和适用条件 |
| C | 有上下文和结果的可核验案例 | 企业官方实施案例、带样本和结果的案例研究、经多材料确认的内部实践 | 只能证明特定条件下有效，不直接上升为普遍规律 |
| D | 有专业价值的二手分析或专家经验 | 咨询观点、专业媒体、专家访谈、会议经验 | 用于解释、补充和提出假设，关键结论需更强证据 |
| E | 线索性或利益相关材料 | 营销文案、个人博客、社区讨论、搜索摘要、AI 摘要 | 只用于发现线索，不得单独支撑关键结论 |

### 5.1 降级条件

出现以下情况时降低证据等级或置信度：

- 无发布日期或已明显过时；
- 没有原始链接、样本、方法或数据口径；
- 发布者对结果有直接商业利益且未披露限制；
- 只报告成功结果，不说明基线、失败样本或实施条件；
- 只有二次转述，无法找到原始材料；
- 内部材料未确认版本、责任人或审批状态。

## 6. 独立性与交叉验证

### 6.1 独立来源判定

以下情况不算多个独立来源：

- 多家媒体转载同一新闻稿；
- 多篇文章引用同一份调查；
- 同一作者或机构对同一案例的重复发布；
- 供应商、合作伙伴和客户共同发布但证据全部来自供应商；
- AI 汇总页面引用相同的二手材料。

### 6.2 关键主张验证

对会影响决策、投入、责任或验收的主张：

1. 优先寻找两类以上独立来源；
2. 至少包含一个 A—C 级来源；
3. 主动寻找反例或失败条件；
4. 记录支持和反对证据；
5. 无法满足时降低为“有限证据”或“待验证假设”。

不要以来源数量替代独立性和质量。

## 7. know-how 提取方法

### 7.1 实践卡字段

对每项做法建立实践卡：

| 字段 | 提取要求 |
|---|---|
| 业务问题 | 写清需要改善的结果或风险 |
| 适用边界 | 行业、规模、阶段、地域、对象和限制 |
| 触发条件 | 什么事件或状态启动该实践 |
| 前置输入 | 数据、材料、权限、人员和上游产物 |
| 流程阶段 | 用结果导向名称描述阶段 |
| 关键动作 | 写成可执行动作，避免“加强、完善、推进” |
| 角色分工 | Responsible、Accountable、Consulted、Informed |
| 工具模板 | 系统、表单、清单、会议和自动化工具 |
| 指标阈值 | 指标、口径、频率、阈值来源和责任人 |
| 验收标准 | 用可观察条件定义完成 |
| 失败模式 | 失败原因、预警信号、影响和补救动作 |
| 证据 | 来源、等级、日期、支持范围和限制 |

### 7.2 从案例中提炼

不要只写“某公司做了什么”。继续追问：

- 当时的业务背景和约束是什么；
- 选择该做法前比较了哪些方案；
- 关键决策和放弃项是什么；
- 哪个动作真正改变了结果；
- 使用了什么基线和指标；
- 结果持续了多久；
- 哪些部分依赖该公司的特殊资源；
- 失败、返工和例外是如何处理的。

### 7.3 从内部访谈和会议中提炼

优先提取：

- 反常识或非共识判断；
- 决策背后的原因和被放弃方案；
- 数字、阈值、步骤、工具和异常处理；
- 已经发生的实际行为，而非理想化描述；
- 带原话或明确记录位置的证据。

无法从材料确认的因果关系不得自行补齐。

## 8. 迁移性评估

分别评估以下维度：

| 维度 | 核心问题 |
|---|---|
| 目标一致性 | 外部实践解决的问题是否与当前目标一致 |
| 场景相似性 | 行业、客户、规模、阶段和复杂度是否相近 |
| 组织能力 | 是否具备所需角色、决策权和协作机制 |
| 数据系统 | 数据是否存在、可用、合规，系统是否支持 |
| 成本时效 | 实施成本和见效周期是否可接受 |
| 风险合规 | 失败影响、法规和客户要求是否允许 |
| 可测量性 | 是否能采集过程和结果指标 |

给出三类结论：

- **直接采用**：关键前提基本一致，风险低，可按标准做法执行。
- **裁剪试点**：部分前提不一致，需要缩小范围验证。
- **暂不采用**：关键能力、数据、权限或合规条件不满足。

迁移判断使用高/中/低置信度，不与 A—E 证据等级混为一谈。

## 9. 置信度表达

- **高置信度**：多个独立的 A—C 级来源一致，边界清楚，存在可观察结果，反例已检查。
- **中置信度**：证据方向一致，但来源数量、独立性、时效或目标场景匹配度有限。
- **低置信度**：主要依赖单一案例、专家观点或二手资料，存在冲突或关键字段缺失。

使用以下表达：

- “多个独立来源在该条件下支持……”
- “这是一个有结果数据的单一案例，尚不能视为行业共识。”
- “现有证据支持把它作为试点假设，不足以直接设为正式标准。”
- “目前信息不足以判断该阈值是否适用于目标场景。”

## 10. 典型错误

- 把“知名企业采用”写成“适合所有企业”；
- 把案例结果与方法之间的相关性写成因果关系；
- 只总结成功做法，不研究失败样本和实施条件；
- 罗列工具而不说明流程、角色和验收；
- 给出看似精确但没有口径和来源的指标；
- 混淆法规要求、行业建议和企业自愿实践；
- 把内部计划、会议讨论或个人判断写成已确认事实；
- 把多篇转载文章当成多个独立证据；
- 只提供研究结论，不给迁移判断和下一步动作。
