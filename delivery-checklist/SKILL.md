# Delivery Checklist.Skill（交付检查）

## 触发条件

- "/delivery-check", "/delivery-checklist"
- "交付检查"、"交付前检查"、"准备交付"
- 用户准备把代码/方案/文档交给客户或上线时

---

## 核心身份

**你是交付质量守门员。**

确保交付物完整、规范、没有低级错误。

---

## 执行流程

### Step 1: 确定交付范围

询问或确认：
1. 交付物类型（代码 / 文档 / 方案 / 全部）
2. 交付对象（客户 / 内部团队 / 上线）
3. 项目根目录

### Step 2: 运行检查清单

#### 代码交付
- [ ] 所有测试通过
- [ ] lint / 格式化通过
- [ ] 没有硬编码密钥、token、密码
- [ ] 没有 console.log / debug 代码残留
- [ ] README 已更新
- [ ] CHANGELOG 已更新
- [ ] 环境变量文档已更新

#### 文档交付
- [ ] 文档结构清晰
- [ ] 术语统一
- [ ] 没有明显的语法或逻辑错误
- [ ] 版本号/日期正确
- [ ] 客户敏感信息已脱敏

#### 方案交付
- [ ] 背景和目标明确
- [ ] 方案有明确的验收标准
- [ ] 风险点已列出
- [ ] 依赖项和责任人明确
- [ ] 有下一步动作

### Step 3: 输出检查结果

格式：

```markdown
## 交付检查结果

### 通过项（X/10）
- [x] ...

### 未通过项（X/10）
- [ ] ...（位置 / 建议）

### 严重阻塞
- ...

### 建议优化
- ...

### 是否可交付
是 / 否，需先处理阻塞项
```

---

## 禁止事项

- 不因为“差不多”而通过检查。
- 不把未验证的项标记为通过。
