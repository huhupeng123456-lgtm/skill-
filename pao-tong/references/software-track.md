# 软件与工具训练轨道

## 适用范围

用于 GUI 软件、CLI 工具、IDE、数据库工具、部署工具和企业应用，例如 Cherry Studio、Dify、Docker、Git、飞书多维表格或剪映。

## 能力地图

不要把“熟悉软件”当目标。按真实工作拆成会改变训练方式的子能力，例如：

- 给一个工作目标，选择正确功能和入口；
- 给一个已有对象，判断当前状态与下一步；
- 从空白创建、配置、运行、保存或导出；
- 读取日志、历史记录或错误状态；
- 条件变化后修改方案；
- 发生高频故障时定位并恢复；
- 在课程或岗位主工具中独立完成完整工作流。

固定菜单名称可以记忆；功能选择属于判别模型；状态变化属于连接模型；熟练操作、排错与完整工作流属于程序性能力。分别选择材料和训练，不统一成点击教程。

## 开始前

1. 确认最终要独立完成的工作结果和未见挑战。
2. 检查操作系统、软件版本、账号、权限、现有项目和可提交证据。
3. 核对课程、老师或岗位的主工具与真实工作流。
4. 使用练习项目、测试账号或可恢复副本；不直接用生产数据训练。
5. 按 [operation-gates.md](operation-gates.md) 处理 GUI 身份、IDE 配置、命令、数据和安全门禁。

## 最小真实任务

选择一条端到端工作流：

- 创建或打开真实工作对象；
- 完成核心判断、配置或编辑；
- 运行、预览或验证结果；
- 保存、导出、发布到测试环境或重新打开；
- 定位日志、状态、历史记录或错误入口；
- 留下可复核产物。

“找到按钮”不是任务完成。验收最终工作结果和状态。

## 训练方式

- 第一条路径可给完整入口和步骤，但每步说明对象、原因、状态变化和观察点。
- 随后撤掉操作顺序，让用户根据目标和当前状态选择功能。
- GUI 使用功能名和当前状态，不以颜色、形状或位置猜控件。
- CLI 说明命令读取什么、改变什么、是否持续运行、去哪里看证据。
- IDE 是目标主工具时，用户要会打开项目、选环境、使用具名运行配置、看日志、断点和停止进程。
- 用户已掌握同构机制时，只训练新工具的差异和集成证据。

## 上层抽象

完成两个或三个结构相似工作流后，让用户比较：

- 哪些入口、字段、文件或参数每次变化；
- 哪个“目标 → 当前状态 → 动作 → 状态变化 → 验证”结构始终不变；
- 面对第四个软件或项目首先要确认什么；
- 哪些版本、权限或数据条件会让原方法失效。

## 变式

一次选择一个会影响结果的变化：输入文件、关键参数、权限、导出格式、环境、目标位置，或从已有对象改为从空白开始。操作前要求用户基于已知机制预测变化；没有合理依据时改成观察实验。

## 故障

选择安全、可恢复的高频故障：路径、端口、版本、依赖、权限、账号、文件占用、配置未保存、格式不兼容、服务未启动或 GUI 进入相似错误入口。

按“现象 → 证据 → 一个原因 → 区分性检查 → 最小修复 → 回归验证”处理，不一次给多个修复方案。

## 未见独立挑战

使用新的输入、项目、状态或约束，只提供目标、安全边界、成果证据和完成条件。完成后让用户说明关键状态变化、不变机制、一个不能照搬的边界和一个故障定位方法。
