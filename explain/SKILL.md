# Explain：意义建构与概念迁移

把用户遇到的符号、术语、定义、文章、课程或技术描述，转化为用户自己的可迁移意义结构。不要把词典解释、中文翻译、术语复述或案例记忆当作理解。

## 职责边界

使用本 Skill，当主要目标是：

- 理解或辨析概念、规律、方法、思维模型和符号意义；
- 判断现实案例属于什么、为什么；
- 阅读课程、论文、文档或代码描述并建立意义；
- 理解关系为什么成立、适用于哪里、能推出什么；
- 解释字段、公式、条件、节点或中间步骤为何需要。

完成标准是用户能正确理解并判断一个未讲过的新案例，不要求完成完整工程任务。

当核心需求变成“我要亲手搭建、配置、运行、调试或独立完成”，停止继续扩展解释，切换到 `pao-tong`。不要在本 Skill 中复制整套操作陪练、故障训练和证据验收。

## 成功标准

针对概念 X，按任务需要让用户能够：

1. 知道符号 X 在当前语境指什么；
2. 知道 X 为什么被划为这一类；
3. 从现实对象中判断 X / 非 X；
4. 区分最容易混淆的相邻概念；
5. 知道 X 在什么关系或过程中发挥作用；
6. 知道适用输入、能得到的输出和重要边界；
7. 处理一个结构同类但表面不同的未见案例。

针对规律、方法或理论，还要说清：

> 输入空间 → 映射关系 → 输出空间

即它什么时候适用、基于什么得到什么、能告诉用户什么、不能告诉什么。

## 内部建构分析

面对“我要理解 X”，先在内部完成以下判断，不机械展示成固定标题：

1. **最终任务**：用户未来面对什么输入，需要产生什么判断、解释或输出。
2. **已见或未见**：只需记固定对应，还是要处理新案例、新需求或新参数。
3. **能力类型**：当前缺的是固定对应、判别模型、连接/处理模型、外显知识，还是需要真实操作的程序性能力。
4. **当前层级**：用户只认识语言或符号，已经建立意义，还是能在现实对象中正确识别。
5. **材料选择**：为当前模型选择正例、反例、边界例、输入输出变化或因果证据，不先追求教程数量。
6. **验收方式**：适合泛化时，用结构相同但表面不同的未见情况验证。

多轮学习、语言材料学习、迁移失败或无法判断用户卡点时，完整读取 [constructive-learning-framework.md](references/constructive-learning-framework.md)，按其中的三层诊断和定向修复处理。

## 语境与符号诊断

先从当前对话推断用户是在第一次理解、比较概念、判断案例、读材料、准备面试、工程分析还是排查问题。只有不同答案会实质改变解释时才追问。

同一个词或符号可能在不同体系中指向不同概念。优先采用用户当前文章、课程、论文、代码、公司规范或技术框架中的定义，不用通用定义覆盖来源定义。必要时明确区分：

- 按这份材料，X 指什么；
- 通用语境是否还有另一种用法；
- 哪些内容是原文，哪些是帮助理解的补充或推断。

用户问英文、缩写、代码符号、字段名时，先判断缺的是：

- 符号是否认得；
- 符号指向哪个现实对象或概念；
- 当前句子或技术体系中的具体词义；
- 概念关系和判断条件；
- 面对现实案例的判别能力。

知道 `agent = 智能体`、知道缩写全称或会复述定义，只能证明语言层成立，不能自动判为理解。

## 建立可迁移意义

### 类别型概念

内部建立四部分：

1. **关系结构**：X 与什么相对，上游输入是什么，下游作用是什么；
2. **内涵**：判为 X 必须满足的关键共有属性；
3. **判别模型**：具体对象 → 检查关键属性 → X / 非 X；
4. **外延**：有哪些代表性对象被判为 X，不追求穷举。

不要把内涵和判别模型混为一谈。前者是判断依据，后者是把依据用于具体对象的过程。

### 连接、规律与方法

明确输入空间、通用关系、输出空间和失效边界。类比只能提出待验证的新模型；说清替换了哪些角色和输入、保留了哪个关系、哪些前提可能失效，以及怎样验证。

### 应用型问题

区分：

- **判别模型**：当前情况属于哪一类；
- **处理模型**：识别为这一类后，会发生什么、下一步怎样处理。

再区分：

- **知识**：描述可泛化关系；
- **决策**：知识 + 当前目标 + 当前约束 → 此刻行动。

不要把“最佳实践是 X”或专家建议直接包装成普遍知识。先说明它依赖的关系、目标和条件。

## 自适应解释流程

根据任务选取必要步骤，不机械输出十个栏目：

1. **先给结论**：用普通话说明 X 在当前语境是什么、主要区分什么。
2. **找到对象层**：指出现实里什么对象、动作、状态或关系对应 X。
3. **放进关系中**：用“输入 → 谁处理或判断 → 输出 → 下一步用途”说明位置。
4. **抽出判断条件**：只保留真正决定 X / 非 X 的少量条件。
5. **训练边界**：用正例、反例，必要时边界例，逐项说明满足或缺少哪个条件。
6. **补连接模型**：解释识别后能推出什么、怎样处理、哪些条件改变后不能套用。
7. **检验未见情况**：学习型请求用新案例检查识别、预测或解释；快速查义和当前工作答案不强制出题。

用户说“我还是不懂”时，不原样重复定义。先诊断是符号未识别、意义未建立、对象层缺失、上层抽象缺失、判别条件错误、输入空间错误，还是处理模型缺失；只补当前缺口。

用户用自己的话解释时：

1. 指出哪些判断正确、哪一处会导致误判；
2. 给一版保持其表达习惯的修正版；
3. 只补一两个决定性遗漏；
4. 用新案例验证修正后的模型。

## 结构性配置解释门禁

建议新增表、字段、复选框、公式、触发条件、工作流节点或中间转换前，必须依次检查：

1. 最终目标是什么；
2. 已观察到什么失败或可验证风险；
3. 系统缺少哪个最小状态、判断或连接；
4. 新组件的唯一职责是什么；
5. 上游输入怎样经过它改变下游动作；
6. 现有字段、关联、状态、公式或节点能否稳定替代；
7. 删除后会出现什么重复、遗漏、误触发或不可验收结果；
8. 加入后用什么记录、状态、日志或结果验收。

随后明确判为：

- **必要**：存在具体失败，且现有能力不能稳定替代；
- **有用但可选**：主要降低成本、增强可读性或便于管理；
- **冗余**：现有可靠能力已表达同一约束，新增会造成重复状态或同步风险。

讲不出具体失败、不可替代职责和可观察证据时，拒绝新增。解释成立后，实际点击与配置交给 `pao-tong`。

## 表达与事实边界

- 先结论，再关系、判断条件、例子和边界；避免百科历史和无关术语。
- 不用一个同样抽象的新词解释旧词，不循环定义。
- 内部可以使用“内涵、外延、输入空间、建构”等词；面向用户默认说“什么算、什么不算、凭什么判断、何时能用、现实里长什么样”。
- 不为了完整列十几个特征，一次只引入当前判断需要的概念。
- 来源不足时标为补充、推断或待确认，不补造材料观点、项目事实或案例结论。
- 默认只在当前对话回答；解释、复习和举例不授权写入知识库或外部系统。
